# End-to-end test report — October 1, 2026

Historical report. Reopening and banner defects below have since been fixed and passed the extended browser regression on October 2. See [the current evidence-to-decision validation](2026-10-02-evidence-to-decision.md).

The application completes the tested courtroom workflows, but the Full Proceeding UI has two reproducible defects. The regression command deliberately exits with status 1 while either defect remains.

The browser smoke test covers an empty workspace, evidence uploads, a bail rehearsal with Crown and defence submissions, exhibit and authority drill-downs, a ruling, debrief, reopening, provider settings, and packet preview.

The new arguments test covers all eleven Full Proceeding steps: corpus preview/import, extraction review, neutral model approval, separate private arguments, disclosure findings, motion docket, admission ledger, autonomous proceeding with a review checkpoint, decision sheet, event audit, and a three-seed robustness lab. The deterministic actors produce nine guilty and three not-guilty ballots; the engine correctly records no verdict and the unmet unanimity warning. The base run has 12 initial and 12 final valid ballots. The three variants retain the base review checkpoint and are resumed through explicit test API approvals. All four runs reach completed status. No browser exceptions or failed API responses were observed.

Argument markers are verified in the correct advocate's model input and absent from the opposing advocate's and jurors' inputs and public submissions. Only source files are imported as evidence. The matter archive preserves the sources, private arguments, events, and decision records. The saved trial remains available through the API after a browser reload.

## Defects

1. **Full Proceeding cannot reopen its saved model/run after reload.** Complete a proceeding, reload the page, open Full Proceeding, and select Decision Sheet. It displays “No decision sheet yet.” The completed trial and identical decision sheet still exist in SQLite and `GET /api/trials/:runId`. The guided component initializes its model and trial to null and has no persisted-run selection/loading flow. Screenshot: `tmp/qa/arguments/reload-missing-decision.png`.
2. **Provider banner reports the legacy panel size in Full Proceeding.** In the criminal run, the banner says “6 jurors” while the decision sheet applies 12-of-12 and the stored run contains twelve profiles and twenty-four ballots. The banner receives the legacy `runConfig`, rather than the full-proceeding configuration. Screenshot: `tmp/qa/arguments/decision.png`.

Neither defect was changed during this testing request. The saved data remained intact.
